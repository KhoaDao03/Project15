# Bleep ATR finish probability

Crypto and commodity paper strategies use `bleep-reference-atr-finish-v5`, implemented in
[`bleep.py`](../src/btc15/strategies/settlement_edge/bleep.py). This ports Bleepblorp
0.2's Normal-CDF finish estimate, asset multipliers, fading indicator adjustment,
safety cap and market-respect cap. Entry thresholds are **83% for crypto** and **85% for commodities**;
the source checkout uses 85%. No other Bleepblorp entry or exit rules are imported.

## Calculation

```text
ATR = max(rolling ATR(14) from official-reference one-minute candles, reference * 0.00015, 1e-8)
sigma = ATR * sqrt(max(seconds_remaining, 1) / 60) * asset_multiplier
z = (reference - strike) / max(sigma, 1e-9)
base_up = NormalCDF(z)
weight = min(0.15, max(seconds_remaining, 0) / 900)
indicator_up = clip(0.5 + 0.12 * indicator_lean, 0.05, 0.95)
p_up = clip((1 - weight) * base_up + weight * indicator_up, 0.02, 0.98)
```

Multipliers are **BTC 1.35, ETH 1.10, SOL 1.00, XRP 1.00**. GOLD, SILVER and WTI use **1.35**, matching BTC. The existing
indicator lean uses Wilder RSI/Stochastic RSI and Bollinger Bands. Project15's
causal candle construction is retained. ATR averages the 14 true ranges from the
last 15 contiguous official-reference candles, including the causal current minute,
matching Bleepblorp's `atrRolling`. It never uses exchange-seeded ATR. If fewer than
15 usable reference candles are available, the relative price floor above is used,
as in Bleepblorp. Invalid numeric ATR rejects evaluation.

Exchange history can still seed Stochastic RSI and Bollinger inputs; these require
33 contiguous minute candles. Missing indicator inputs block evaluation. Reference
gap, freshness and quality checks remain independent entry gates. Records expose
`reference_rolling_atr` and `atr_source`, distinguishing measured ATR from the floor.

### Indicator adjustment parity

The indicator lean now matches Bleepblorp 0.2's `indicatorLean` rules:
turning Stochastic RSI below 25 / above 75 uses ±0.85; band-edge fades begin
at ±0.75 normalized Bollinger position with the same direction checks;
outside-band reversals use ±0.55 and soft band pressure uses ±0.45.
Momentum/reversal selection uses a 0.10 margin and Bleepblorp's reversal
preference for qualifying ties. Breakout overrides and fading weight are retained.
A fixture generated by executing the original TypeScript checks 378 boundary cases.

This matches the lean function for identical inputs. Reference candle completeness,
indicator history, feed sources and the user-selected 83% entry threshold remain
Project15 settings; this does not claim identical outputs from different live inputs.

The safety ratio is `abs(reference - strike) / max(sigma, 1e-9)`. Below 0.5,
favored-side confidence is capped at 78% (five points below the requested 83%
entry floor). The active presets enable this check. YES is mapped according to
the contract comparator; model NO probability is exactly one minus model YES.

## Market-respect cap and entry

Selected-side confidence is the smaller of the safety-adjusted model probability
and `clip(clip((bid + ask) / 2, 0.01, 0.99) + premium, 0.02, 0.98)`.
The premium is **0.06 for BTC/ETH/GOLD/SILVER/WTI** and **0.10 for SOL/XRP**. Missing or invalid
quotes cannot qualify. Capping one side does not increase the other side's odds.

`p_yes/no` remain the model probabilities; `conservative_probability` in the
entry decision is the capped confidence. The decision records the pre-market-cap
probability and whether the cap applied. Caps are recalculated from each current
book even when model inputs are cached, and rechecked at paper/live submission.

All four cloud presets require **confidence ≥83%** and
**1 < seconds_remaining ≤420**. The standard/late confirmation boundary remains
120 seconds, with the same 83% floor on both sides. Exactly 420 seconds is eligible;
exactly 1 second is blocked. Price, quality, freshness, confirmation,
risk and execution checks remain additional requirements. The separate directional
Bollinger entry veto is disabled across all seven presets; the indicator adjustment
inside the probability model is unchanged. The 80–95¢ purchase
range and 99¢ take-profit / 55¢ hard-stop settings are unchanged.

## Settlement evidence and limitations

The ATR finish estimate models spot finishing across the strike; it is **not** a
model of the final-minute arithmetic settlement average. Project15 still validates
the actual sample grid and computes settlement-average mean/uncertainty separately
for late-side selection and confirmation. Reference realized volatility affects
those diagnostics and quality checks, not the crypto finish sigma. Fully observed
settlement uses the contract's actual rounding/comparison; official outcomes
remain authoritative for settlement processing.

Commodity paper markets share the ATR finish predictor with BTC settings, while
retaining their Pyth terminal settlement rules. All seven paper presets use a
99¢ take-profit and 55¢ hard stop. There
is no user-selectable second crypto predictor or blend. New model identity and
configuration hashes prevent silently resuming an old-model checkpoint. Prepare
fresh cloud configurations; existing running installations are not migrated by
editing presets.

These are uncalibrated model estimates and confidence caps, not established win
rates or evidence of profitability. Normal price increments can miss jumps.

Commodity presets require **confidence ≥85%** for both standard and late entries,
after the same safety and market-respect caps. Their ATR multiplier remains 1.35.
